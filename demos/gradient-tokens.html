Siren gradient colour tokens

A colour token such as --siren-node-fill or --siren-edge-stroke can hold url(#id) pointing at a <linearGradient>, <radialGradient> or <pattern> the page puts in its own <defs>. View source: the whole recipe is one <style> block and one zero-size <svg>. The node fills use the default objectBoundingBox units; the edges use userSpaceOnUse, which is why the straight horizontal edges below stay visible, arrowheads and all. Render is re-gradiented on its own through [data-siren-id="Render"].

Limits, spelled out in README › Gradients and patterns: a CSS linear-gradient() is not SVG paint and renders black with no diagnostic; a horizontal or vertical straight edge stroked with an objectBoundingBox gradient disappears, so stroke tokens need userSpaceOnUse, whose coordinates are the diagram's, not each edge's direction; arrowheads follow the gradient through context-stroke, which Safari lacks; the highlight's stroke transition cannot interpolate between a paint server and a colour, so it switches instantly; an SVG copied out of the page loses the gradients, because the <defs> stay behind; and the page keeps its gradient ids unique. --siren-highlight-color must stay a colour — the glow uses it inside drop-shadow().
