Siren flowchart edges and subgraphs

examples/flowchart-edges.srn — every arrow form Mermaid has for a flowchart edge, in one release pipeline. An arrow token is not a name out of a list of seventeen: it decomposes into a line (-- solid, == thick, -.- dotted, or its short .-), an end on each side (nothing, > an arrow, o a circle, x a cross), and a length. So A <-.-> B is not an eighteenth arrow — it is a dotted line with an arrow on each end, and A ----> B is a plain arrow that holds its target three ranks away instead of one, which is the one part of the token that changes the layout rather than the drawing. An edge carries a label in either spelling — A -->|green| B and A -- pass --> B produce identical documents — and dagre keeps room for it, so the text lands in a gap rather than over a box. subgraph … end groups the nodes written inside it and nests; the frames are addressed by a generated id (subgraph:1, subgraph:2, subgraph:3), never by the author's title, because a group may legitimately be named after a node. Step through it to watch that: a frame animates under its generated id exactly as a node animates under its own, and a highlight step still beats a dotted or thick line, which is why those strokes are emitted as a CSS class rather than as an inline declaration. linkStyle 6 paints the seventh edge declared, and both halves land: the stroke colours the line and its arrowhead, the color colours the label, so the edge that says “green” is green.
